# Configuration

Read this reference when changing configuration models, JSON names or defaults,
the in-game config dialog, save behavior, property-change subscribers, restart
requirements, or configuration documentation.

## Schema ownership

[`UiTweaksModConfig`](../../src/UI-Tweaks/ModConfig/ModConfig.cs) is the root object
stored as `ui-tweaks.json`.

| JSON path | Model | Runtime owner |
| --- | --- | --- |
| `zoom` | `ZoomConfig` | `ZoomFeature` |
| `tweaks` | `GameTweaksConfig` | `GameTweaksFeature` and `GameStatusService` |
| `hud.tooltips` | `TooltipsConfig` | `GameStatusFeature` and `HudTooltipLabel` |
| `quickSearch` | `QuickSearchConfig` | `QuickSearchFeature` and `QuickSearchGuiDialog` |

`TooltipsConfig` contains predefined tooltip objects, a demonstration-only
`exampleCustomTooltip`, and the `customTooltips` list. The example object is serialized
as a template but [`GameStatusFeature`](../../src/UI-Tweaks/ModFeatures/GameStatusFeature.cs)
deliberately excludes it from HUD creation.

## Load and persistence flow

[`GetModConfig`](../../src/UI-Tweaks/Extensions/GetModConfigExtension.cs) loads the
root object during client startup and stores it again, which persists defaults added
by newer model versions. A load exception is logged and replaced by a stored default
object. Manual file changes are therefore startup inputs; there is no file-watching
reload path.

The in-game flow is:

```text
control callback
  -> mutate the shared config object
  -> NotifyPropertyChanged on the owning model
  -> ModConfigContext.SaveConfig()
  -> Debouncer waits 10 seconds after the last edit
  -> StoreModConfig(ui-tweaks.json)
```

[`ModConfigDialog`](../../src/UI-Tweaks/Gui/Dialogs/ModConfigDialog.cs) publishes one
live config instance and the save trigger through `ModConfigContext`. Reconfiguring or
disposing the dialog flushes a pending save before disposing its debouncer, so closing
the dialog does not lose queued edits.

Config properties are ordinary setters: they do **not** raise events or save
automatically. Every editor callback must:

1. validate and mutate the intended value;
2. call `NotifyPropertyChanged` on the object observed by the runtime consumer;
3. use the correct property name, including the owning aggregate property for nested
   value objects such as `Offset` and `Padding`;
4. call `SaveConfig`.

## Runtime effect timing

| Setting | Effect timing |
| --- | --- |
| `QuickSearch.Enable` | Startup gate. Changing it cannot create or dispose `QuickSearchFeature` in the current lifecycle. |
| `QuickSearch.ResultListHeight` | Live only when Quick Search started. Its dialog listens to config changes and recomposes on the main thread. |
| `Zoom.Enable` | Startup gate. Changing it cannot create or dispose `ZoomFeature` in the current lifecycle. |
| Zoom strength, speed, and vignette | Read from the shared config by the running feature during zoom calculations; `ZoomFeature` does not subscribe to `PropertyChanged`. |
| `GameTweaks.CorrectCalendarYear` | Live. `GameTweaksFeature` listens for this exact property and applies or removes its Harmony patch. |
| Existing tooltip option properties, including `Enable` | Live. Each created `HudTooltipLabel` listens to its option object, rebuilds its composer/subscriptions, and opens or closes as needed. |
| Membership of `CustomTooltips` | Startup-defined. `GameStatusFeature` creates labels from the list once; later collection mutations do not create or remove labels. |

For the feature-level startup rules, also read
[`6.lifecycle.md`](6.lifecycle.md).

## Configuration dialog map

- `Shift+N` toggles `ModConfigDialog` through the shared `GuiDialogHost`.
- Root pages are General, Zoom, and Tooltips.
- `ModConfigContext` gives descendant pages the shared model and save trigger.
- `ModConfigPageNavigator` owns root/detail navigation and breadcrumbs. Navigation
  requests a scoped reconciliation of the dialog tree.
- The Tooltips page lists the predefined runtime tooltip configurations and pushes a
  shared detail page for the selected option.
- The dialog mutates the same model instances held by already-running features; it
  does not clone, stage, or roll back edits.

User-facing names, defaults, and placeholder documentation belong in
[`docs/src/03.configuration.md`](../../docs/src/03.configuration.md); keep that page
aligned when the serialized schema or visible behavior changes.
