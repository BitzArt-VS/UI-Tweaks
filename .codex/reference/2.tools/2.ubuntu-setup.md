# Ubuntu Setup

Use the repository setup script when an Ubuntu or WSL environment does not already have the .NET 10 SDK:

```bash
bash .codex/scripts/ubuntu/setup.sh
```

The script accepts no arguments. It verifies that the distribution is Ubuntu, runs `sudo apt-get update`, installs `dotnet-sdk-10.0`, and prints the resulting .NET environment. It warns when the environment does not appear to be WSL but continues on regular Ubuntu.

This setup changes system packages and requires network access and sudo approval. Do not run it during normal development when `dotnet --list-sdks` already shows a compatible .NET 10 SDK.

After setup, use the restore, build, and test commands from the [.NET reference](1.dotnet.md).

## Codex notification sounds

To configure personal Codex question and response-completion sounds in WSL, run:

```bash
bash .codex/scripts/ubuntu/notification-sounds-setup.sh
```

The script accepts no arguments. It requires Ubuntu on WSL with WSLg and a systemd user service. It installs `pulseaudio-utils`, creates a per-user sound service, backs up and updates `~/.codex/config.toml`, and plays question and completion test sounds. The service runs outside the Codex sandbox; sandboxed Codex commands only append events to a private file under `/tmp`. Completion notifications are accepted only when the Codex payload contains a real user input and assistant response for a persisted user thread; ephemeral startup and background threads are ignored. Event diagnostics are written without message content to `/tmp/codex-notification-sound-<user-id>.log`.

This setup changes system packages and personal files under `~/.codex` and `~/.config/systemd/user`. It requires network access and sudo approval. Reload VS Code or start a new Codex session after the script succeeds.
