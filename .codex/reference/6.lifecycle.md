# Lifecycle

Read this reference when changing the mod entry point, feature registration or
ordering, configuration activation timing, event or renderer ownership, Harmony
patching, or disposal.

## Feature lifecycle references

- [Zoom](6.lifecycle/1.zoom.md) — Zoom renderer activation, stability, and cleanup.

## Startup

1. [`UiTweaksModSystem`](../../src/UI-Tweaks/UI-Tweaks/ModSystems/UiTweaksModSystem.cs) is a
   client-only Vintage Story mod system.
2. It loads `ui-tweaks.json` through
   [`GetModConfig`](../../src/UI-Tweaks/UI-Tweaks/Extensions/GetModConfigExtension.cs). A valid
   loaded config is stored again so newly introduced defaults are persisted. A load
   failure is logged and replaced with a newly stored default config.
3. It constructs features in dependency order. `GuiDialogHostFeature` must precede
   consumers of the shared dialog host.
4. The base [`ModSystem`](../../src/UI-Tweaks/UI-Tweaks/ModSystems/Base/ModSystem.cs) filters
   features through `ShouldLoad(Client)`, then starts them in list order.

Feature startup is isolated: a feature that throws is logged and disposed without
preventing later features from starting. A failure in the mod system's own startup
path disposes the whole system.

## Activation timing

`QuickSearchFeature` starts on every client session and listens to its config
notifications. Each notification checks the current `QuickSearch.Enable` value and
registers or removes the Quick Search hotkey, so it can be enabled or disabled
without a restart. Disabling also closes an open Quick Search dialog.

`ZoomFeature` starts on every client session and listens to its config notifications.
Each notification checks the current `Zoom.Enable` value and registers or removes
the Zoom hotkey, so Zoom can be enabled or disabled without a restart. Disabling
also clears any held Zoom request before removing the hotkey.

Already-running features may handle other values live. In particular,
[`GameTweaksFeature`](../../src/UI-Tweaks/UI-Tweaks/ModFeatures/GameTweaksFeature.cs) listens
for `CorrectCalendarYear` changes and applies or removes its Harmony transpiler
without a restart.

[`MealIndicatorFeature`](../../src/UI-Tweaks/UI-Tweaks/ModFeatures/MealIndicatorFeature.cs)
starts on every client session and reconciles its Harmony postfix against the current
`ShowMealRemainingIndicator` value after any `GameTweaksConfig` notification. Applying
or removing the postfix marks every slot in the player's currently available inventories
dirty so cached overlays refresh without a restart.

## Cleanup invariants

- The mod system attempts to dispose every feature even when another feature's
  disposal throws.
- Each feature owns cleanup for the events, renderers, dialogs, HUD elements, and
  Harmony patches it registered.
- Harmony features remove only patches belonging to their own Harmony ID.
- Meal-indicator cleanup removes its postfix and refreshes cached inventory overlays.
- Zoom cleanup restores shared field-of-view and mouse-sensitivity factors to `1`.
- New features belong in the ordered feature list in `UiTweaksModSystem`; their
  partial-start cleanup and repeat-safe disposal are part of the lifecycle contract.
