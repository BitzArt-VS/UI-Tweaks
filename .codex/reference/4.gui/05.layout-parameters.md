# Layout and Arrangement

Layout is a single component-owned arrangement operation. There is no separate measurement pass or `Measure(...)` contract. The framework starts arrangement at tree roots; each component decides when and in what order to arrange its descendants through their mounted slots.

## Layout Parameters

`GuiComponentLayoutParameters` is reset and configured during reconciliation, then consumed by component `Arrange()` implementations.

| Property | Type | Default | Notes |
| --- | --- | --- | --- |
| `Margin` | `GuiThickness` | Zero | Outside the component box; contributes to flow spacing |
| `Padding` | `GuiThickness` | Zero | Inside the component box; defines its descendant content area |
| `Width` | `GuiSize` | Auto | Explicit constraint; takes precedence over `WidthMode` when resolvable |
| `Height` | `GuiSize` | Auto | Explicit constraint; takes precedence over `HeightMode` when resolvable |
| `WidthMode` | `GuiSizeMode` | `FitContent` | Used when `Width` is Auto |
| `HeightMode` | `GuiSizeMode` | `FitContent` | Used when `Height` is Auto |
| `Positioning` | `GuiComponentPositioning` | Relative | Relative participates in flow; absolute does not |
| `HorizontalAlignment` | `GuiHorizontalAlignment` | Left | Positions a resolved child within horizontal slack |
| `VerticalAlignment` | `GuiVerticalAlignment` | Top | Positions a resolved child within vertical slack |

`GuiThickness` is `(Top, Right, Bottom, Left)`. Its horizontal and vertical totals are used for box and flow calculations.

`GuiSize` represents Auto, a fixed logical-pixel extent, or a fraction such as `"50%"`. Fractional values resolve against an available ancestor or flow extent and may have minimum and maximum clamps.

`GuiLayoutSize` is a position-independent `(Width, Height)` pair.

`GuiComponentBounds` combines an optional position with an optional size:

```csharp
public readonly record struct GuiComponentBounds(
    GuiPoint? Position,
    GuiLayoutSize? Size);
```

`Position` is the top-left reference point. Logical X increases rightward and logical Y increases downward.

## Arrangement States

`IGuiComponent.Arrange()` returns a `GuiComponentBounds` value. `GuiSlot.Arrange()` is a command that caches the component result in `GuiSlot.Bounds`, which still has one nullable state during the transition:

1. Slot-level `Bounds == null` — no cached arrangement result is currently available.
2. Non-null with `Size == null` — arrangement ran, but size is unresolved.
3. Non-null with `Size != null && Position == null` — size is resolved, but position is not.
4. Non-null with `Size != null && Position != null` — size and position are resolved.

Size may remain unresolved while it depends on a parent percentage, fill space, previous siblings, wrapped-text width, or shared table tracks. When only position is unresolved, return the known size without inventing an origin.

Each component-slot `Arrange()` call invokes the mounted component and caches its returned bounds. A component may assign provisional bounds to its own slot before arranging descendants; its returned final bounds replace that provisional value. `slot.Bounds` otherwise exposes the latest result without initiating arrangement. Repeated sequential calls re-evaluate dependencies; `slot.IsArranging` exposes current execution state, and recursive entry into the same component slot is rejected.

## Size Resolution

Resolution priority per dimension is:

1. A resolvable explicit `Width` or `Height`.
2. `FitContent`, derived during `Arrange()` from intrinsic content or arranged descendants.
3. `Fill`, derived from the available ancestor or flow extent.

Fixed values resolve without ancestor size. Fractions and Fill may remain unresolved until the required extent exists. Position resolution is independent: a component can return a valid size before an ancestor position is known.

Padding is included in the component's arranged size. Margin remains outside the component bounds and contributes only to separation and flow.

## Default Flow

`GuiComponent` provides stack-like horizontal flow with line wrapping:

1. Visit relative descendants in declaration order.
2. Arrange them from left to right inside the component's content area.
3. If the next descendant's outer width would exceed the available content width, start a new line.
4. Advance each new line by the tallest outer box in the preceding line.
5. Exclude absolute descendants from flow.
6. Inline layout-transparent wrappers without adding a component box.

An unresolved descendant size can make the containing flow size unresolved. An unresolved ancestor position does not prevent the flow from calculating its size.

Horizontal wrapping is the only default flow. A row-filling descendant naturally forces the next descendant onto a new line, producing column-like layouts without a direction mode. Fundamentally different layouts own that behavior in their `Arrange()` implementation.

## Positioning and Alignment

Relative components participate in their parent's flow. Absolute components are positioned independently and do not advance the flow cursor.

Alignment applies only when the relevant parent extent and child size are known. It changes position within slack and never enlarges the component. A size-only result can remain cached until enough ancestor state exists to resolve alignment and position.

## Specialized Layouts

### Tables

A table owns shared row and column dependencies. It may:

1. Arrange descendants to collect known sizes.
2. Resolve track sizes across multiple rows and cells.
3. Re-arrange affected descendants after shared constraints change.
4. Return bounds with `Size == null` while a required track size remains unresolved.

This dependency order belongs to the table component, not to a universal framework traversal.

### Multi-span text

Multi-span text is intentionally not generalized into fragmented component bounds. A `GuiTextBlock` owns lightweight span values and private per-line geometry for drawing, selection, and precise hit testing. The text block itself exposes one component arrangement.

## Configuring Layout

Layout parameters are set through named arguments on declaration helpers or through `ConfigureLayout(...)`:

| Argument | Effect |
| --- | --- |
| `width: x` / `height: y` | Sets fixed or fractional explicit constraints |
| `widthMode: m` / `heightMode: m` | Sets the Auto fallback mode |
| `fill: true` | Sets both modes to Fill |
| `margin: t` / `padding: t` | Sets outer and inner spacing |
| `positioning: p` | Selects Relative or Absolute positioning |
| `horizontalAlignment: a` | Selects horizontal alignment |
| `verticalAlignment: a` | Selects vertical alignment |

External configuration overrides defaults registered by the component's own `ConfigureSlot`.

## Layout-transparent Wrappers

A pure `IGuiNode` has no layout parameters and introduces no layout box. Its descendants pass through at the wrapper's declaration position and participate in the nearest component-owned flow.

The wrapper's visual and input extent is derived from arranged descendants. This supports tooltips, hover decorators, debug overlays, and cascading-value providers without perturbing layout. Absolute positioning belongs to descendants inside the wrapper.

Public authoring and type constraints remain:

- `Add<T>` accepts any `IGuiNode`.
- Layout arguments and `ConfigureLayout<T>` apply only to `IGuiComponent`.
- `Configure<T>` and input callbacks work for both components and transparent nodes.
