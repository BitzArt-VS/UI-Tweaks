# Layout and Arrangement

Layout is a single component-owned arrangement operation. There is no separate measurement pass or `Measure(...)` contract. The framework starts arrangement at tree roots; each component decides when and in what order to arrange its descendants through their mounted slots.

## Layout Parameters

`GuiComponentLayoutParameters` is reset and configured during reconciliation, then consumed by component `Arrange()` implementations.

| Property | Type | Default | Notes |
| --- | --- | --- | --- |
| `Margin` | `GuiThickness` | Zero | Outside the component box; contributes to flow spacing |
| `Padding` | `GuiThickness` | Zero | Inside the component box; defines its descendant content area |
| `MinimumWidth` | `GuiLengthRule?` | `null` | Optional lower bound applied to the resulting width |
| `Width` | `GuiLengthRule?` | `null` | Optional explicit constraint; takes precedence over `WidthMode` when resolvable |
| `MaximumWidth` | `GuiLengthRule?` | `null` | Optional upper bound applied to the resulting width |
| `MinimumHeight` | `GuiLengthRule?` | `null` | Optional lower bound applied to the resulting height |
| `Height` | `GuiLengthRule?` | `null` | Optional explicit constraint; takes precedence over `HeightMode` when resolvable |
| `MaximumHeight` | `GuiLengthRule?` | `null` | Optional upper bound applied to the resulting height |
| `WidthMode` | `GuiSizeMode` | `FitContent` | Used when `Width` is null |
| `HeightMode` | `GuiSizeMode` | `FitContent` | Used when `Height` is null |
| `Positioning` | `GuiComponentPositioning` | Relative | Relative participates in flow; absolute does not |
| `HorizontalAlignment` | `GuiHorizontalAlignment` | Left | Positions a resolved child within horizontal slack |
| `VerticalAlignment` | `GuiVerticalAlignment` | Top | Positions a resolved child within vertical slack |

`GuiThickness` is `(Top, Right, Bottom, Left)`. Its horizontal and vertical totals are used for box and flow calculations.

`GuiLengthRule` represents a fixed logical-pixel rule or a fractional rule such as `"50%"`. Layout declarations use `null` to indicate that no explicit rule overrides the corresponding size mode. `Resolve` accepts an available numeric extent and returns resolved logical pixels. It returns `null` when a fractional rule has no available extent. Component-level minimum and maximum constraints apply to the resulting dimensions regardless of whether they came from explicit lengths, Fill, or FitContent.

`GuiSize` is a position-independent `(Width, Height)` pair of nullable resolved logical-pixel values. Inside arranged bounds, each dimension is either `null` for unlimited space or a numeric extent; fractional rules belong only to layout declarations.

`GuiComponentBounds` combines an optional position with an optional size:

```csharp
public readonly record struct GuiComponentBounds(
    GuiPoint? Position,
    GuiSize? Size);
```

`Position` is the top-left reference point. Logical X increases rightward and logical Y increases downward.

## Arrangement States

`IGuiComponent.Arrange()` returns a `GuiComponentBounds` value. Calling `GuiSlot.Arrange()` on a `GuiComponentSlot` runs the guarded slot lifecycle, invokes the component, and caches its result in `GuiComponentSlot.Bounds`. Its nullable states have distinct meanings:

1. `GuiComponentSlot.Bounds == null` — no cached arrangement result is currently available.
2. Non-null bounds with `Size == null` — arrangement ran, but size is unknown.
3. A non-null size with `Width == null` — width is unlimited.
4. A non-null size with `Height == null` — height is unlimited.
5. A non-null size with both dimensions null — size is unlimited in both directions.
6. `Position == null` — position is not yet established, independently of size.

Size may remain unknown while it depends on a parent percentage, fill space, previous siblings, wrapped-text width, or shared table tracks. A known size may expose an unlimited axis while descendants arrange. When only position is unknown, return the known size without inventing an origin.

`GuiSlot.Arrange()` keeps `IsArranging` true throughout the guarded operation and rejects recursive entry into the same slot. Its `private protected OnArrange()` hook contains only subtype behavior: `GuiComponentSlot` invokes the mounted component, while `GuiNodeSlot` immediately calls `ArrangeChildren()`. A component may assign provisional bounds to its own component slot before arranging descendants; its returned final bounds replace that provisional value. `componentSlot.Bounds` otherwise exposes the latest result without initiating arrangement, and repeated sequential calls re-evaluate dependencies.

## Size Resolution

Resolution priority per dimension is:

1. A resolvable explicit `Width` or `Height`.
2. `FitContent`, derived during `Arrange()` from intrinsic content or arranged descendants.
3. `Fill`, derived from the available ancestor or flow extent.

Fixed values resolve without ancestor size. Fractions and Fill may remain unresolved until the required extent exists. Position resolution is independent: a component can return a valid size before an ancestor position is known.

Padding is included in the component's arranged size. Margin remains outside the component bounds and contributes only to separation and flow.

## Intended Default Flow

`GuiComponent.Arrange()` currently establishes provisional-bounds, descendant-arrangement, and completed-bounds phases, whose implementations still throw `NotImplementedException`. The following stack-like horizontal flow with line wrapping is the intended future default:

1. Visit relative descendants in declaration order.
2. Arrange them from left to right inside the component's content area.
3. If the next descendant's outer width would exceed the available content width, start a new line.
4. Advance each new line by the tallest outer box in the preceding line.
5. Exclude absolute descendants from flow.
6. Inline layout-transparent wrappers without adding a component box.

An unresolved descendant size can make the containing flow size unresolved. An unresolved ancestor position does not prevent the flow from calculating its size.

Horizontal wrapping is the only default flow. A row-filling descendant naturally forces the next descendant onto a new line, producing column-like layouts without a direction mode. Fundamentally different layouts own that behavior in their `Arrange()` implementation.

## Positioning and Alignment

Relative components participate in their parent's flow. Absolute components are positioned independently and do not advance the flow cursor.

Alignment applies only when the relevant parent extent and child size are known. It changes position within slack and never enlarges the component. A size-only result can remain cached until enough ancestor state exists to resolve alignment and position.

## Specialized Layouts

### Tables

A table owns shared row and column dependencies. It may:

1. Arrange descendants to collect known sizes.
2. Resolve track sizes across multiple rows and cells.
3. Re-arrange affected descendants after shared constraints change.
4. Return bounds with `Size == null` while a required track size remains unresolved.

This dependency order belongs to the table component, not to a universal framework traversal.

### Multi-span text

Multi-span text is intentionally not generalized into fragmented component bounds. A `GuiTextBlock` owns lightweight span values and private per-line geometry for drawing, selection, and precise hit testing. The text block itself exposes one component arrangement.

## Configuring Layout

Declaration helpers do not accept general layout arguments. Set every external layout override through `ConfigureLayout(...)`:

| Configuration | Effect |
| --- | --- |
| `layout.Width = x` / `layout.Height = y` | Sets fixed or fractional explicit constraints |
| `layout.WidthMode = m` / `layout.HeightMode = m` | Sets the fallback size mode |
| Set both modes to `Fill` | Fills both available axes |
| `layout.Margin = t` / `layout.Padding = t` | Sets outer and inner spacing |
| `layout.Positioning = p` | Selects Relative or Absolute positioning |
| `layout.HorizontalAlignment = a` | Selects horizontal alignment |
| `layout.VerticalAlignment = a` | Selects vertical alignment |

For example:

```csharp
builder.AddLabel(0, "Status")
    .ConfigureLayout(layout =>
    {
        layout.WidthMode = GuiSizeMode.Fill;
        layout.Margin = new GuiThickness(0, 0, 4, 0);
    });
```

External layout configuration overrides defaults registered by the component's own `ConfigureSlot`.

## Layout-transparent Wrappers

A pure `IGuiNode` has no layout parameters, component slot, or arrangement bounds. Its node slot remains arranging while `ArrangeChildren()` invokes guarded `GuiSlot.Arrange()` operations on direct descendants in declaration order. Those descendants pass through at the wrapper's declaration position and participate in the nearest component-owned flow.

The wrapper's visual and input extent is derived from arranged descendants. This supports tooltips, hover decorators, debug overlays, and cascading-value providers without perturbing layout. Absolute positioning belongs to descendants inside the wrapper.

Public authoring and type constraints remain:

- `Add<T>` accepts any `IGuiNode`.
- `ConfigureLayout<T>` applies only to `IGuiComponent`.
- `Configure<T>` and input callbacks work for both components and transparent nodes.
