# Rendering Pipeline

The framework renders through `GuiElementAdapter`, a minimal Vintage Story dialog that participates in normal dialog ordering and focus. It uses draw order `0.2`, matching vanilla inventory, container, handbook, and configuration dialogs so Vintage Story can bring the focused dialog to the front within that shared layer. The adapter forwards rendering and input to `DialogRenderer` and `GuiInputRouter`.

## Frame Flow

For each GUI frame, `DialogRenderer`:

1. Advances the focused node through `OnFrame(deltaTime)`.
2. Drains scheduled subtree reconciliations.
3. Detects dialog-size or GUI-scale changes.
4. Runs an arrange or paint-only walk when dirty.
5. Blits the latest main texture.
6. Updates and blits floating layers.

An unchanged frame only blits existing textures.

## Invalidation Levels

| Request | Use when | Work performed |
| --- | --- | --- |
| `RequestReconcile()` | Child declarations or configured values may change | Rebuilds the affected subtree, then arranges and paints |
| `RequestArrange()` | Bounds, clipping, scrolling, or input regions may change | Recomputes layout and regions, caches bounds, and paints |
| `RequestPaint()` | Only visual state changed | Paints using cached bounds without rebuilding layout or input regions |

`RequestRender()` is a compatibility alias for `RequestPaint()`.

Arrange work already paints the surface, so the renderer does not run a second paint-only walk in the same frame.

## Cairo Surface and Coordinates

- Component layout and drawing use logical pixels.
- The Cairo context is scaled by `RuntimeEnv.GUIScale` before component drawing.
- The backing `ImageSurface` and uploaded texture use physical pixels.
- A size or scale change reallocates the backing surface and requests a fresh draw.
- Dirty draws clear the surface, paint the tree, upload the texture, and then use premultiplied-alpha blitting.

Save and restore Cairo state around local transforms. Do not apply GUI scale manually in component layout code.

## Dialog Bounds and Measurement

The dialog is a normal keyed component slot. Standard dialogs must declare fixed root width and height through `ConfigureSlot`; the renderer validates those dimensions after reconciliation.

Descendants use the regular measurement and layout path. `FitContent` delegates to `IGuiComponent.Measure`, and the base `GuiComponent` measures its mounted children. See [Layout parameters](05.layout-parameters.md) for sizing and positioning rules.

## Dialog Hosting

- `GuiDialogHostFeature` initializes the default static `GuiDialogHost` during client startup and disposes it with the feature.
- Normal feature code uses `GuiDialogHost.Open`, `Toggle`, and `Close`.
- A host keeps at most one renderer per dialog type. Opening an existing dialog with configuration reconciles that instance instead of creating a duplicate.
- Use `GuiDialogHostInstance` only when isolated dialog ownership is intentional.
- Closing a dialog removes and disposes its adapter and renderer. Mounted nodes are disposed when their concrete types implement `IDisposable`.
- Renderers accept any `class, IGuiDialog, new()`; inheriting `GuiDialog` is convenient but not required.

## Floating Layers

Tooltips and overlays render on separate Cairo surfaces so they can extend beyond the main dialog bounds. `FloatingLayerRenderer` wraps its active fragment in a root `GuiContainer`, measures it with the placement constraints, draws it, and blits it after the main surface.

Floating layers reuse the same component measurement rules as the main tree. Overlay layers may forward input regions to the dialog router; tooltip layers are visual-only. See [Tooltips](06.tooltips.md) for tooltip-specific behavior.

## Input and Focus

`GuiElementAdapter` forwards mouse, keyboard, focus, and Escape events to `GuiInputRouter`.

- Mouse input uses arranged regions and reverse-order hit testing.
- Keyboard input goes to the root dialog slot first, then the focused node when still unhandled.
- Mouse-down inside a dialog or interactive overlay requests native dialog focus.
- Clicks outside the dialog and overlays remain available to other dialogs, HUD elements, or the world.
- Mouse wheel input is consumed only while the surface is focused and hovered.
- Escape blurs a focused component first; a later Escape with nothing focused closes the dialog.

See [Mouse events](07.mouse-events.md) and [Keyboard events](08.keyboard-events.md) for detailed dispatch rules.

## Resizing

`IGuiResizable` is a capability separate from `IGuiComponent`. During arrangement, the builder records resize regions for arranged nodes whose `SupportedResizeEdges` is not `None`. `GuiInputRouter` checks those regions before normal mouse hit testing and delegates proposed bounds to the target.

`GuiDialog` opts into resizing through `IsResizable`, applies its min/max constraints, updates dialog size and screen-centred offsets, and requests the required redraw. The default dialog resize edges are right, bottom, and their corner. Custom cursor assets live under `resources/assets/bitzartuitweaks/textures/gui/cursors/`.
