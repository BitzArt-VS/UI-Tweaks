# Component Model

The framework separates tree participation, arrangement, resizing, and dialog behavior into small contracts. Interfaces define node capabilities, while `GuiSlot` and `GuiComponentSlot` are framework-owned mounted runtime contracts. The provided base classes are optional; `GuiComponent` does not yet provide its intended default arrangement behavior.

## Public Contracts

| Contract | Responsibility |
| --- | --- |
| `IGuiNode` | Render fragment, attachment, lifecycle, frame updates, and drawing hooks |
| `IGuiComponent` | Adds layout participation through `LayoutParameters` and parameterless `Arrange()` |
| `IGuiResizable` | Extends a component with supported resize edges and framework-suggested bounds |
| `IGuiDialog` | Adds screen-centred offsets and optional dialog-runtime attachment to a component |
| `GuiSlot` | Exposes a node's framework-owned mounted position, structural and layout ancestry, children, guarded current-slot and immediate-child arrangement, arrangement state, and runtime requests |
| `GuiComponentSlot` | Adds component-owned arrangement bounds to a mounted `IGuiComponent` |

`GuiNode` is the base for layout-transparent wrappers. `GuiComponent` currently throws `NotImplementedException` from its virtual `Arrange()` placeholder until default arrangement is implemented. `GuiDialog` adds normal dialog runtime, focus, close, movement, and resizing behavior.

## Node Lifecycle

`IGuiNode` provides:

- `TreeFragment`
- `Attach(slot)`
- `ConfigureSlot(builder)`
- `OnInitialized()`
- `OnParametersSet()`
- `OnFrame(deltaTime)`
- `Render(context, bounds)`
- `RenderOverlay(context, bounds)`

Attachment happens once after construction. The attached `GuiSlot` exposes the node's immediate structural `Parent`, nearest layout-participating `LayoutParent`, `Children`, guarded current-slot `Arrange()`, and immediate-child `ArrangeChildren()` operations, making the mounted tree navigable and usable by direct interface implementations. `LayoutParent` is a `GuiComponentSlot`, skips layout-transparent nodes, and is `null` when there is no component ancestor; root-level slots have no parent. A mounted `IGuiComponent` receives a `GuiComponentSlot`, whose `Bounds` property stores its arrangement result. Initialization happens on first mount. Parameters are applied on every reconciliation pass. `OnFrame` runs once per GUI frame while the node is focused. `RenderOverlay` runs after the node's children but before later siblings.

The reconciliation order and keyed identity rules are documented in [Reconciliation](02.reconciliation.md).

## Configuration Lifecycle

Render-tree declarations describe the full state for the current pass, not a delta from the previous pass.

For a reused slot, the framework:

1. Clears configuration and callback actions from the previous pass.
2. Resets layout parameters to framework defaults for layout components.
3. Applies the node's own `ConfigureSlot` defaults and callbacks.
4. Applies external `Configure`, `ConfigureLayout`, and callbacks.
5. Runs lifecycle methods and reconciles children.

Re-register configuration on every `BuildComponentTree` pass. External layout configuration overrides component defaults. Own-slot and external event callbacks are additive, with own-slot callbacks running first.

Use `ConfigureSlot(IGuiSlotBuilder)` for defaults and events attached to a component's own bounds. Use external builder configuration for values owned by the parent declaration.

## Declaring Components

Public authoring goes through extension methods:

- `Add<T>(key)` declares any `IGuiNode` without assuming that it participates in layout.
- `AddLabel` and other component-specific `Add*` helpers choose only conveniences meaningful to their component.
- `.Configure(Action<T>)` applies component state.
- `.ConfigureLayout(...)` applies layout state to any declared `IGuiComponent`.
- `.OnMouse*`, `.OnKey*`, and `.OnFocusChanged` attach slot callbacks.
- `AddCascadingValue<T>` publishes an ambient value to a declared subtree.

Declaration helpers do not accept general layout arguments or attempt to enumerate every layout combination. Use `ConfigureLayout(...)` for every external layout override, including minimum and maximum constraints. Components register their own defaults through `ConfigureSlot`. A pure `IGuiNode` is layout-transparent, so configure layout on its children instead. See [Layout parameters](05.layout-parameters.md).

There is no `AddContainer` helper. Declare `GuiContainer` and its subclasses through `Add<T>(key)`, then assign `Content` and other component state through `.Configure(...)`. `GuiContainer` remains available during its deprecation period, but new public authoring APIs must not depend on inheriting from it.

The low-level builder registration methods are internal. Add new public authoring helpers as extension methods rather than exposing builder internals.

## Arrangement

Sizing and positioning are one component-owned operation:

```csharp
public interface IGuiComponent : IGuiNode
{
    GuiComponentLayoutParameters LayoutParameters { get; }

    GuiComponentBounds Arrange();
}
```

`IGuiComponent.Arrange()` takes no arguments and always returns a `GuiComponentBounds` value. During the transition, slot-level arrangement may still expose nullable cached results. A component reads its mounted slot to inspect its structural parent, nearest layout parent, siblings, descendants, and previously calculated arrangement results. The framework initiates arrangement at tree roots; each component owns descendant traversal and chooses when and in what dependency order to call descendant slots.

```csharp
public abstract class GuiSlot
{
    GuiSlot? Parent { get; }
    GuiComponentSlot? LayoutParent { get; }
    IReadOnlyList<GuiSlot> Children { get; }

    bool IsArranging { get; }

    void Arrange();
    private protected abstract void OnArrange();
    void ArrangeChildren();
}

public sealed class GuiComponentSlot : GuiSlot
{
    GuiComponentBounds? Bounds { get; set; }
}
```

Component-owned traversal supports both normal flow and dependency-sensitive layouts. A stack can arrange descendants in flow order, while a table can inspect and recalculate cells across multiple rows before finalizing shared tracks.

`GuiSlot.Arrange()` rejects recursive entry, sets `IsArranging` for the complete operation, invokes the `private protected OnArrange()` slot hook, and resets state in a `finally` block. `GuiSlot.ArrangeChildren()` invokes `Arrange()` on immediate children in declaration order; it does not flatten or otherwise reinterpret the structural tree. `GuiComponentSlot` implements the hook by invoking the mounted component and caching its returned bounds. `GuiNodeSlot` implements it by calling `ArrangeChildren()`; nested transparent child slots repeat that behavior, recursively reaching component slots without adding a node-level arrangement contract. A component may assign provisional bounds to its own component slot before arranging descendants; the returned final bounds replace that provisional value. Reading `Bounds` does not initiate arrangement, and repeated sequential calls re-evaluate dependencies.

Arrangement uses distinct nullable states:

1. `GuiComponentSlot.Bounds == null` — no cached arrangement result is currently available.
2. Non-null bounds with `Size == null` — arrangement ran, but the component does not know its size yet.
3. A non-null size with `Width == null` — width is unlimited.
4. A non-null size with `Height == null` — height is unlimited.
5. A non-null size with both dimensions null — size is unlimited in both directions.
6. `Position == null` — position is not yet established, independently of size.

Unknown size and unlimited dimensions are intentionally different. A component returns `Size == null` while it still depends on unresolved inputs such as a parent percentage, remaining flow space, wrapped-text width, or shared table tracks. It returns a non-null size containing null dimensions when descendants may arrange without a limit on those axes.

`GuiComponentBounds` is deliberately minimal:

```csharp
public readonly record struct GuiComponentBounds(
    GuiPoint? Position,
    GuiSize? Size);
```

`GuiSize.Width` and `GuiSize.Height` are nullable resolved logical-pixel values; `null` represents an unlimited axis. Fractional rules belong only to layout declarations. `GuiLengthRule.Resolve` accepts an available numeric extent and returns resolved logical pixels, or `null` when a fraction has no available extent. `Position` is the top-left reference point. Logical X increases rightward and logical Y increases downward. Keeping position, size, and per-axis limits distinct lets components expose known constraints without inventing missing geometry.

Pure `IGuiNode` wrappers remain layout-transparent and own no arrangement bounds. Their node slots remain arranging while forwarding through `ArrangeChildren()` to direct descendants in declaration order, without introducing a layout box. Drawing derives a wrapper's visual and input extent from positioned descendants.

`GuiComponent.Arrange()` is currently an explicit `NotImplementedException` placeholder. Its intended default behavior is documented in [Layout parameters](05.layout-parameters.md), but is not yet implemented. Direct `IGuiComponent` implementations have the same mounted-slot capabilities and do not need to inherit from `GuiComponent`.

## Choosing an Invalidation Request

| Change | Request |
| --- | --- |
| Child declarations or configured values depend on changed state | `RequestReconcile()` |
| Cached arrangement results, clipping, scrolling, or input regions may be stale | `RequestLayout()` |
| Existing arrangement results are valid and only visuals changed | `RequestRender()` |

Base-derived and direct interface implementations issue reconciliation, layout, and render requests through their attached `GuiSlot`.

## Cascading Values

`AddCascadingValue<T>(value, content, name?)` creates a lexical scope without adding a component or layout slot.

Consumers use `GetCascadingValue<T>` or `TryGetCascadingValue<T>` from `GuiNode`; direct implementations use `GuiSlot.TryGetCascadingValue<T>`.

Resolution uses the exact type and optional name. The nearest matching scope wins, and an unnamed lookup matches only an unnamed provider. Read cascading values during `OnParametersSet` when the component needs a per-pass snapshot.

## Dialog Components

`IGuiDialog` extends `IGuiComponent` with `OffsetX`, `OffsetY`, and optional runtime attachment. Hosts and renderers accept any `class, IGuiDialog, new()`.

Use `GuiDialog` for normal dialogs. It provides:

- Runtime attachment and protected close/focus helpers.
- Native dialog focus tracking.
- Screen-centred offsets and movement.
- Optional resizing through `IGuiResizable`.

Set default dialog dimensions in `ConfigureSlot` so reconciliation can reset and reapply them. Register dialog-wide keyboard and focus behavior on the root slot. Implement `IDisposable` only when a dialog or child node owns resources; slot removal disposes nodes that opt in.

Dialogs do not own an `Open`, `Close`, or `IsOpen` state. They request closure, and the host owns their lifetime.
