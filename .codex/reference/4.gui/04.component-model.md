# Component Model

The framework separates tree participation, measurement, layout, resizing, and dialog behavior into small interfaces. Prefer the provided base classes unless a custom implementation needs a narrower contract.

## Interface Hierarchy

| Contract | Responsibility |
| --- | --- |
| `IGuiNode` | Render fragment, attachment, lifecycle, frame updates, and drawing hooks |
| `IGuiMeasurable` | Reports desired content size through `Measure(available)` |
| `IGuiComponent` | Combines node and measurement behavior and adds `LayoutParameters` |
| `IGuiResizable` | Accepts framework-suggested outer bounds for supported resize edges |
| `IGuiDialog` | Adds screen-centred offsets and optional dialog-runtime attachment to a component |

`GuiNode` is the base for layout-transparent wrappers. `GuiComponent` adds default child measurement and layout participation. `GuiDialog` adds normal dialog runtime, focus, close, movement, and resizing behavior.

## Node Lifecycle

`IGuiNode` provides:

- `RenderFragment`
- `Attach(slot)`
- `OnInitialized()`
- `OnParametersSet()`
- `OnFrame(deltaTime)`
- `Render(context, bounds)`
- `RenderOverlay(context, bounds)`

Attachment happens once after construction. Initialization happens on first mount. Parameters are applied on every reconciliation pass. `OnFrame` runs once per GUI frame while the node is focused. `RenderOverlay` runs after the node's children but before later siblings.

The reconciliation order and keyed identity rules are documented in [Reconciliation](02.reconciliation.md).

## Configuration Lifecycle

Render-tree declarations describe the full state for the current pass, not a delta from the previous pass.

For a reused slot, the framework:

1. Clears configuration and callback actions from the previous pass.
2. Resets layout parameters to framework defaults for layout components.
3. Applies the node's own `ConfigureSlot` defaults and callbacks.
4. Applies external `Configure`, `ConfigureLayout`, inline layout arguments, and callbacks.
5. Runs lifecycle methods and reconciles children.

Re-register configuration on every `BuildRenderTree` pass. External layout configuration overrides component defaults. Own-slot and external event callbacks are additive, with own-slot callbacks running first.

Use `ConfigureSlot(IGuiSlotBuilder)` for defaults and events attached to a component's own bounds. Use external builder configuration for values owned by the parent declaration.

## Declaring Components

Public authoring goes through extension methods:

- `Add<T>(key, ...)` declares any `IGuiNode`.
- `AddContainer`, `AddLabel`, and other `Add*` helpers provide common component declarations.
- `.Configure(Action<T>)` applies component state.
- `.ConfigureLayout(...)` applies layout state to `IGuiComponent` slots.
- `.OnMouse*`, `.OnKey*`, and `.OnFocusChanged` attach slot callbacks.
- `AddCascadingValue<T>` publishes an ambient value to a declared subtree.

Layout arguments apply only to `IGuiComponent` slots. A pure `IGuiNode` is layout-transparent, so configure layout on its children instead. See [Layout parameters](05.layout-parameters.md).

The low-level builder registration methods are internal. Add new public authoring helpers as extension methods rather than exposing builder internals.

## Measurement

`IGuiMeasurable.Measure(available)` returns desired content size. `GuiComponent.Measure` uses `GuiComponentLayout.MeasureContent` to measure mounted child slots with the framework's stack rules.

- Leaf components override `Measure` for intrinsic size.
- Containers may call `base.Measure` or `GuiComponentLayout.MeasureContent` and adjust the result.
- Direct `IGuiComponent` implementors can use the public `GuiComponentLayout` helpers.
- `FitContent` calls measurement; bounded `Fill` does not.

## Choosing an Invalidation Request

| Change | Request |
| --- | --- |
| Child declarations or configured values depend on changed state | `RequestReconcile()` |
| Existing tree needs new bounds, clipping, scrolling, or input regions | `RequestLayout()` |
| Existing bounds are valid and only visuals changed | `RequestRender()` |

`GuiNode` exposes reconciliation to subclasses. `GuiComponent` also exposes layout and render requests. Direct interface implementations use the attached `IGuiNodeSlot`.

## Cascading Values

`AddCascadingValue<T>(value, content, name?)` creates a lexical scope without adding a component or layout slot.

Consumers use `GetCascadingValue<T>` or `TryGetCascadingValue<T>` from `GuiNode`; direct implementations use `IGuiNodeSlot.TryGetCascadingValue<T>`.

Resolution uses the exact type and optional name. The nearest matching scope wins, and an unnamed lookup matches only an unnamed provider. Read cascading values during `OnParametersSet` when the component needs a per-pass snapshot.

## Dialog Components

`IGuiDialog` extends `IGuiComponent` with `OffsetX`, `OffsetY`, and optional runtime attachment. Hosts and renderers accept any `class, IGuiDialog, new()`.

Use `GuiDialog` for normal dialogs. It provides:

- Runtime attachment and protected close/focus helpers.
- Native dialog focus tracking.
- Screen-centred offsets and movement.
- Optional resizing through `IGuiResizable`.

Set default dialog dimensions in `ConfigureSlot` so reconciliation can reset and reapply them. Register dialog-wide keyboard and focus behavior on the root slot. Implement `IDisposable` only when a dialog or child node owns resources; slot removal disposes nodes that opt in.

Dialogs do not own an `Open`, `Close`, or `IsOpen` state. They request closure, and the host owns their lifetime.
